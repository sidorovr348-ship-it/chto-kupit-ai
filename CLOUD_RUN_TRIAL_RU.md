# Изолированное испытание Cloud Run — My AI Unified

Это инструкция для отдельного тестового сервиса. Она НЕ переводит production-трафик и НЕ меняет текущий адрес приложения.

## Перед запуском

- Нужен Google Cloud project с включённой оплатой и правами на Cloud Run, Cloud Build и Artifact Registry.
- Бесплатные квоты не означают гарантированную стоимость 0 ₽: возможны расходы на сборку, реестр образов, исходящий трафик и превышение квот. Перед запуском настройте бюджет и уведомления.
- Не передавайте API-ключи через Git, Dockerfile или командную строку, которая может сохраниться в истории. Секреты храните в Secret Manager.
- Для временного публичного испытания ограничьте максимальное число экземпляров и следите за расходами. Публичный API без собственной авторизации может использовать посторонний трафик.

## Развёртывание из этой ветки

Из Cloud Shell, в клонированном репозитории и именно на ветке `experiment/cloud-run-trial-2026-10-18`:

```bash
gcloud config set project YOUR_GOOGLE_CLOUD_PROJECT_ID
gcloud run deploy my-ai-unified-trial \
  --source . \
  --region europe-west1 \
  --port 8080 \
  --timeout 60 \
  --max 1
```

При первом запуске Google Cloud может предложить включить необходимые API и создать репозиторий Artifact Registry. Следуйте подсказкам консоли. Сервис по умолчанию не должен получать production-домен.

Для публичного браузерного теста нужно отдельно разрешить неаутентифицированный вызов сервиса в настройках Cloud Run. Делайте это только для временного испытания и с контролем расходов. Не добавляйте production API-ключи в репозиторий.

## Обязательная настройка AI

До теста добавьте необходимые ключи через Secret Manager и подключите их к тестовому сервису. В зависимости от используемых провайдеров это могут быть `GROQ_API_KEY`, `DEEPSEEK_API_KEY`, `MISTRAL_API_KEY`, `PARALON_API_KEY`, `OPENAI_API_KEY` и `SERPER_API_KEY`. Наличие переменной ещё не доказывает, что ключ действителен или что квота провайдера доступна.

## Критические ограничения, которые надо проверить

1. Приложение использует файловую память и состояние лабораторного контура. На Cloud Run локальные файлы временные и не являются надёжным постоянным хранилищем; при перезапуске/масштабировании память может пропасть или разделиться между экземплярами. Этот пробный контейнер пока не решает перенос постоянного хранилища.
2. Локальный Ollama по умолчанию ожидается на `127.0.0.1:11434`; в Cloud Run его отдельного процесса нет. Для AI-ответов необходимо проверить внешние провайдеры и их секреты. Локальный fallback не считается работающим без отдельного Ollama-сервиса.
3. Веб-интерфейс `smart-index.html` пока указывает на production API `https://ai.aliceq.ru`. Сам по себе тестовый Cloud Run сервис не переключит интерфейс на новый backend. Не используйте production-страницу как доказательство тестирования Cloud Run, пока не будет безопасно подготовлен отдельный тестовый интерфейс.
4. Этот Dockerfile не подтверждён успешной сборкой или развёртыванием в Google Cloud. Успех будет заявлен только после реальной сборки, проверки `/health`, `/autonomy/status`, нескольких последовательных `/chat` запросов, TTS и отдельного теста на iPhone.

## Результат

Испытание считается успешным только после фиксации URL тестового сервиса, ревизии, журналов, времени ответов и прохождения повторных запросов. Успех тестового сервиса не означает готовность production-приложения.
